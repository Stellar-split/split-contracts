# Issues #869, #870, #871, #872 — Redemption tokens, Recipient delegation, Time-lock, Advanced pricing

Implements four new extension modules on the `SplitContract`:
- `redemption_ext.rs` (#869)
- `recipient_delegation_ext.rs` (#870)
- `timelock_ext.rs` (#871)
- `pricing_ext.rs` (#872)

Each module adds new entry points, events, storage keys, types, and errors to the
core `split` contract without modifying any existing behaviour.

---

## #869 — Invoice redemption tokens for secondary markets

**New file:** `contracts/split/src/redemption_ext.rs`

**Core functionality**

A creator can issue `RedemptionToken` records after an invoice reaches `Released`
status. Each token carries a `claim_amount` and is owned by a `holder` address.
Tokens can be freely transferred between addresses (enabling a secondary market)
and redeemed to receive the underlying funds from the contract.

**Entry points**
- `issue_redemption_token(creator, invoice_id, holder, claim_amount, expires_at)` — creator only; invoice must be `Released`; returns new token id.
- `transfer_redemption_token(invoice_id, token_id, from, to)` — holder only; blocked if already redeemed or expired.
- `redeem_token(invoice_id, token_id, holder)` — holder only; transfers `claim_amount` of the invoice token to the holder.
- `get_redemption_token(invoice_id, token_id)` — returns `Option<RedemptionToken>`.
- `get_redemption_token_count(invoice_id)` — total tokens issued for an invoice.

**Events**
- `(split, rdm_iss, invoice_id)` — token issued
- `(split, rdm_xfr, invoice_id)` — token transferred
- `(split, rdm_use, invoice_id)` — token redeemed

**New storage keys**
- `InvoiceKey::RedemptionTokenCount(invoice_id)` — running counter per invoice
- `CompoundKey::RedemptionToken(invoice_id, token_id)` — individual token record

**New types:** `RedemptionToken` in `types.rs`

**New errors:** `RedemptionTokenNotFound`, `TokenAlreadyRedeemed`, `TokenExpired`, `NotTokenHolder`

**Tests:** 6 unit tests in the module covering: cannot issue on pending, count starts at zero, transfer non-existent errors, get non-existent returns None, redeem non-existent errors, only creator can issue.

## #870 — Recipient delegation with performance tracking

**New file:** `contracts/split/src/recipient_delegation_ext.rs`

**Core functionality**

A recipient can delegate their payout address to another address for a specific
invoice, optionally with an expiry timestamp. The delegation is resolved
transparently when funds are routed. Aggregate performance metrics
(`invoices_listed`, `invoices_released`, `invoices_refunded`, `total_received`)
are tracked per-recipient.

**Entry points**
- `set_recipient_delegation(invoice_id, recipient, delegate, expires_at)` — recipient only; recipient must be on the invoice.
- `revoke_recipient_delegation(invoice_id, recipient)` — recipient only; must have an active delegation.
- `get_recipient_delegation(invoice_id, recipient)` — returns `Option<RecipientDelegation>`.
- `resolve_recipient_address(invoice_id, recipient)` — returns the effective payout address.
- `get_recipient_performance(recipient)` — returns `RecipientPerformance` (zero if no history).
- `record_recipient_performance(caller, recipient, amount, released, refunded)` — admin only; updates performance metrics.

**Internal helpers (pub(crate))**
- `resolve_payout_address` — used by the release path to route to the delegate when set and not expired.
- `record_recipient_payout` — updates performance counters after a release or refund.

**Events**
- `(split, dlg_set, invoice_id)` — delegation set
- `(split, dlg_rev, invoice_id)` — delegation revoked
- `(split, rcp_perf)` — performance stats updated

**New storage keys**
- `CompoundKey::RecipientDelegation(invoice_id, recipient)` — delegation record
- `AddressKey::RecipientPerformance(recipient)` — aggregate metrics

**New types:** `RecipientDelegation`, `RecipientPerformance` in `types.rs`

**New errors:** `DelegationExpired`, `NoDelegation`

**Tests:** 7 unit tests covering: set/get delegation, revoke, resolve returns delegate, resolve returns recipient when no delegation, performance defaults to zero, revoke with no delegation errors, delegation with expiry.

## #871 — Invoice time-lock mechanisms

**New file:** `contracts/split/src/timelock_ext.rs`

**Core functionality**

A creator can place a selective time-lock on an invoice that independently blocks
`pay`, `release`, and/or `refund` operations until a specified `unlock_at` Unix
timestamp. The lock expires automatically once `unlock_at` is passed and can also
be removed early by the creator.

**Entry points**
- `set_invoice_timelock(creator, invoice_id, unlock_at, lock_payments, lock_release, lock_refund)` — creator only; `unlock_at` must be in the future.
- `remove_invoice_timelock(creator, invoice_id)` — creator only; errors if no lock is configured.
- `get_invoice_timelock(invoice_id)` — returns `Option<InvoiceTimeLock>`.
- `is_action_timelocked(invoice_id, action_name)` — returns bool; `action_name` is `"pay"`, `"release"`, or `"refund"`.

**Internal helper (pub(crate))**
- `assert_timelock_permits(env, invoice_id, action)` — used by `pay`, `release`, and `refund` paths to enforce the lock.

**Events**
- `(split, tl_set, invoice_id)` — time-lock configured
- `(split, tl_rem, invoice_id)` — time-lock removed

**New storage key:** `InvoiceKey::TimeLock(invoice_id)`

**New type:** `InvoiceTimeLock` in `types.rs`

**New errors:** `TimeLockActive`, `NoTimeLock`

**Tests:** 7 unit tests covering: set/get, remove, remove non-existent errors, only creator can set, action-specific check, expired lock not active, past unlock_at rejects.

## #872 — Advanced invoice pricing model

**New file:** `contracts/split/src/pricing_ext.rs`

**Core functionality**

A creator can attach a tiered volume-discount pricing model to an invoice, with
an optional surge multiplier. The effective price for a given `amount` is:

```
effective = base_price * (10_000 - discount_bps) / 10_000
```

If surge is active, the result is further multiplied by `surge_bps / 10_000`.
The highest tier whose `min_amount ≤ amount` applies.

**Entry points**
- `set_invoice_pricing(creator, invoice_id, base_price, tiers, surge_bps)` — creator only.
- `set_invoice_surge(creator, invoice_id, active)` — creator only; errors if already in requested state.
- `get_invoice_pricing(invoice_id)` — returns `Option<InvoicePricingModel>`.
- `compute_effective_price(invoice_id, amount)` — returns `amount` unchanged if no model is set.

**Events**
- `(split, prx_set, invoice_id)` — pricing model configured
- `(split, prx_srg, invoice_id)` — surge toggled

**New storage key:** `InvoiceKey::PricingModel(invoice_id)`

**New types:** `InvoicePriceTier`, `InvoicePricingModel` in `types.rs`

**New errors:** `NoPricingModel`, `SurgeStateUnchanged`

**Tests:** 4 unit tests covering: set/get model, no model returns amount, tier discount applied correctly, surge toggle and idempotency guard, only creator can set.
