# Acquisition referrer registration, 30-day lifecycle test, emergency pause entry points, partial-refund guards

Each issue gets its core piece plus tests. The remaining requirements are listed under "Not done in this PR".

## #792 - acquisition referral revenue

**Done**
- `register_acquisition(new_user, referrer)`: requires `new_user` auth, one-time only ("acquisition already registered"), rejects self-referral. Stored under `(acq_ref, new_user)`.
- `get_acquisition_referrer(user) -> Option<Address>`.
- `AcquisitionRegistered` event (`split`, `acq_reg`, new_user; data = referrer).
- Tests: register stores the referrer and emits the event, double registration rejected, self-referral rejected.

**Not done in this PR**
- Crediting `acquisition_referral_bps` (default 1%) of the protocol fee on invoices from referred creators.
- `claim_acquisition_rewards` and the `AcquisitionRewardEarned` event.

## #793 - 30-day invoice lifecycle integration test

The repo-root `tests/` directory is not part of any crate (the root `Cargo.toml` is a virtual workspace), so a test there would never be compiled. The test lives in `contracts/split/tests/integration.rs`, which `cargo test --workspace` runs.

**Done**
- `test_full_30_day_lifecycle`: create a 300-unit invoice split 200/100 on day 0 (held until day 30 with `scheduled_release_at`), three payers contribute 100 on days 1, 5 and 10 (asserting `funded`, payer and contract balances after each), then `trigger_scheduled_release` on day 30. Final assertions: `Released`, recipients received 200/100, contract balance 0.

**Not done in this PR**
- Deadline-extension vote (day 25), pause/resume (days 26-27), 50% partial release (day 28), note (day 29).
- Event assertions via `env.events().all()` and history-log assertions.

## #800 - emergency pause of all invoices

Already on `main`: admin-only `pause` / `unpause` set the contract-wide flag that `pay`, `release` and `refund` check (`require_fn_not_paused` -> `require_not_paused`).

**Done**
- `pause_all_invoices(admin)` / `resume_all_invoices(admin)` built on the same admin check and flag, emitting `InvoiceSystemPaused` (`split`, `sys_pause`) / `InvoiceSystemResumed` (`split`, `sys_resm`).
- Tests: paused -> `pay` panics and the event is emitted; resumed -> `pay` succeeds; non-admin cannot pause.

**Not done in this PR**
- A typed `InvoiceSystemPausedError` (the panic stays "contract is paused").
- Dedicated release / refund blocked-while-paused tests.

## #801 - partial refund before deadline

Already on `main`: `partial_refund(creator, invoice_id, bps)` refunds `bps / 10_000` of each payer's payment and emits `partial_refund_issued`.

**Done**
- Guards: rejected once the deadline has passed ("invoice deadline has passed") and when the invoice is fully funded ("invoice is fully funded").
- Tests (the first in the repo for `partial_refund`): single partial refund, two consecutive partial refunds, refund after the deadline rejected, fully funded invoice rejected. The two guard tests fail on `main`.

**Not done in this PR**
- `RefundInitiated` / `RefundProcessed` events.
- A test that payers can contribute again after a partial refund.
